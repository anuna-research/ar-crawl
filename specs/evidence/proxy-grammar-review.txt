[P1] Bound recognition cost before feeding attacker-controlled proxy fields to Nearley.
Location: playwright-service/proxy-input.js:24-28; playwright-service/proxy-grammar.json:22-24.
The shared grammar permits arbitrarily long right-recursive labels, and the 63-character semantic limit runs only after the entire input has been parsed. A short malformed HTTP request can therefore monopolize the browser service event loop before rejection. The service body parser (server.js:3531-3537) imposes no size limit. Reproduced locally with parseInput('wire-endpoint', 'http://' + 'a'.repeat(n) + ':80'): n=5,000 took 737ms, n=10,000 took 2,885ms, n=20,000 took 17,779ms. These are synchronous execution times; no browser/network activity is required. The old bounded hostname validation did not incur this parser cost. Add a declared, shared recognition budget / input length bound before parser.feed (with the matching Racket boundary behavior), or grammar/recognizer changes that reject oversized fields incrementally. Cover long labels, digit sequences and bypass lists with a bounded-time regression. If introducing an overall length limit, declare it in CON-103 rather than silently changing the accepted language.
